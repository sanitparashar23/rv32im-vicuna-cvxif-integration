# Synthesis Results

Logic synthesis of the complete integrated design (`rv32im_top`: RV32IM
scalar core + Vicuna RVV coprocessor via CV-X-IF) using Cadence Genus
21.14-s082_1, targeting the GPDK045 (Nangate/GlobalFoundries-derived
academic 45nm) standard cell library, slow corner
(`slow_vdd1v2_basicCells_lvt.lib`, PVT_1P08V_125C).

## Results Summary

| Metric | Value |
|---|---|
| Target frequency | 100 MHz (10 ns period) |
| Timing closure | **MET** -- 355 ps positive slack |
| Critical path data delay | 9,500 ps |
| Total cell count | 327,915 |
| Total area | 388,015.553 um^2 |
| Total power | 42.0929 mW |
| Synthesis errors | 0 (Fatal=0, Error=0 -- "Normal exit") |

Full detail: [`reports/area_with_mem.rpt`](reports/area_with_mem.rpt),
[`reports/timing_with_mem.rpt`](reports/timing_with_mem.rpt),
[`reports/power_with_mem.rpt`](reports/power_with_mem.rpt),
[`reports/gates_with_mem.rpt`](reports/gates_with_mem.rpt),
[`reports/messages_with_mem.rpt`](reports/messages_with_mem.rpt).

The critical path (`u_cpu_u_pc/PC_reg[6]/CK -> u_cpu_u_pc/PC_reg[31]/D`) is
dominated by ripple-carry-style combinational logic in the PC-generation
path -- consistent with the ripple-carry ALU/PC-adder bottleneck identified
in the thesis's future-work section (Carry-Lookahead / parallel-prefix
adders proposed as the fix for scaling beyond 100 MHz).

## Why 45nm (GPDK045) and not a smaller node

GPDK045 was chosen because it is freely available for academic use and
sufficient to prove synthesizability and closure at the 100 MHz target.
A smaller node (e.g. 28nm) was considered but not pursued: achieving
100 MHz was already representative of the design's structural limits (see
critical-path note above) rather than a node-limited constraint, and a
smaller academic-tier node with comparable open access was not available
for this work. See `docs/5g-phy-scaling-estimate.md` (pending) for a
literature-based discussion of what a smaller node might offer.

## Memory implementation: register arrays, not SRAM macros

The `power_with_mem.rpt` breakdown shows the `memory` category at exactly
zero (leakage, internal, switching, and total all 0.0), while `register`
accounts for 92.22% of total power. This is expected and worth stating
explicitly: this flow used only the standard-cell library
(`gsclib045_all_v4.4`), with no SRAM compiler or memory macro library
attached. The `(* ram_style = "block" *)` synthesis attribute in
`i_mem_synth.sv` / `d_mem_synth.sv` is a hint, not a guarantee -- without a
memory compiler available, Genus mapped both instruction and data memory
arrays down to flip-flop-based register arrays rather than dedicated SRAM
macros. This is almost certainly the dominant contributor to the high
total cell count (327,915) -- a real SRAM macro of equivalent capacity
would use a small fraction of the area. This is a normal and expected
limitation of an academic synthesis flow without foundry memory-compiler
access, not a modeling error.

## Files in this directory

| File | Purpose |
|---|---|
| `synth_with_mem.tcl` | **The synthesis script that actually produced the results above.** Uses synthesis-safe memory models (`i_mem_synth.sv`, `d_mem_synth.sv`) and `rv32im_top_synth.sv`. |
| `synth_final.tcl` | An earlier synthesis attempt using the simulation-style memory models (with `$readmemh`, not synthesizable). This produced empty area/power reports and was superseded by `synth_with_mem.tcl`. Kept here for reference/history only -- do not use this script to reproduce results. |
| `i_mem_synth.sv` | Synthesis-safe instruction memory: adds `clk`/`rst` ports and registered read, removing the simulation-only `$readmemh` construct. |
| `d_mem_synth.sv` | Synthesis-safe data memory: removes `$readmemh` and the simulation-only `initial` block; write/read logic otherwise unchanged from `rtl/scalar_core/d_mem.sv`. |
| `rv32im_top_synth.sv` | Synthesis-safe top-level module, wiring in the `_synth` memory variants and their added `clk`/`rst` ports. |
| `synthesis_with_mem_100MHz.log` | Full Genus run log for the `synth_with_mem.tcl` flow. 0 errors, 0 fatal, "Normal exit". |
| `reports/` | The five reports generated by `synth_with_mem.tcl` (area, timing, power, gates, messages). |

## Reproducing

This flow depends on the GPDK045 (`gsclib045_all_v4.4`) library path
configured via `set_db init_lib_search_path` in `synth_with_mem.tcl`,
which is specific to the academic tool environment (EDA Playground /
Cadence cloud) this was run on and will need to be updated to point at a
locally available copy of the library to reproduce elsewhere.
